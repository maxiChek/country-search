# Архитектурные решения (Design Decisions)

Этот документ описывает ключевые архитектурные и дизайнерские решения, принятые в ходе разработки приложения Country Search.

## 1. Отмена устаревших запросов (AbortController вместо флага)

Для обработки ситуации гонки (race condition), когда пользователь печатает быстро и в полете находится несколько запросов, мы используем комбинацию `AbortController` и счетчика `requestId` (см. `src/searchController.ts`).

**Как это работает:**

1. При запуске нового поиска вызывается `cancelInFlight()`. Он отменяет предыдущий `AbortController` и очищает таймаут.
2. Создается новый `AbortController`, и его `signal` передается в `fetch()` в `searchCountries.ts`.
3. Одновременно инкрементируется `requestId`. Когда ответ приходит, мы проверяем `myId === requestId`. Если нет — результат отбрасывается.

**Почему именно так, а не просто флагом «актуальный ли это ответ»?**

- **Экономия трафика:** Флаг (например, `isLatest`) просто игнорирует ответ _после_ того, как он полностью скачался и распарсился. `AbortController` же реально обрывает сетевой запрос на уровне браузера, экономя трафик, память и освобождая пул соединений. Для мобильных сетей это критично.
- **Нагрузка на бэкенд:** Отмена запроса посылает сигнал отмены (TCP RST или отмену HTTP/2 стрима), что снижает лишнюю нагрузку на API.
- **Двойная защита:** `requestId` работает как страховка. Если сетевой запрос разрешится ровно в ту же миллисекунду, когда пользователь ввел новый символ, `AbortController` может не успеть. `requestId` гарантирует, что даже если старый запрос проскочит, его данные не перезапишут новый стейт.

## 2. Обоснование задержки debounce (300 мс)

В `src/main.ts` контроллер инициализируется с `debounceMs: 300`.

**Почему 300 мс?**

- **Скорость печати:** Средняя скорость печати — около 150–200 мс между нажатиями. Задержка в 300 мс гарантирует, что мы дождемся, пока пользователь закончит печатать слово (или сделает паузу), прежде чем идти в API.
- **Восприятие пользователя:** 300 мс — это общепринятый порог «мгновенного» отклика интерфейса. Это ощущается отзывчиво, но при этом не спамит бэкенд.

**Что будет, если убрать задержку (0 мс)?**
Каждое нажатие клавиши вызовет сетевой запрос. Ввод слова "United States" (13 символов) вызовет 13 запросов почти мгновенно. Это приведет к лишнему трафику, потенциальному превышению лимитов API (429 Too Many Requests) и подтормаживанию UI.

**Что будет, если сильно увеличить (например, 1000 мс)?**
Интерфейс станет вялым. Пользователь напечатает запрос, посмотрит на экран и будет ждать целую секунду, прежде чем появится спиннер. Это ломает ощущение «живого поиска».

## 3. Сложность (Big O)

### `mapCountryResponse` (`src/mapCountryResponse.ts`)

- **Временная сложность:** `O(1)` на одну страну. Функция выполняет фиксированное число операций (проверка типов, доступ к свойствам, создание объекта) независимо от размера входа.
- **Общая сложность маппинга массива:** При вызове `raw.map(mapCountryResponse)` на массиве из `N` стран сложность составляет `O(N)`, где `N` — количество результатов от API (обычно небольшое число, < 50).
- **Пространственная сложность:** `O(1)` дополнительной памяти на страну, итого `O(N)` для массива результатов.

### Бонус: Кэш / Дедупликация (если применимо)

- _Примечание: если бы был реализован кэш, он бы использовал `Map`._
- **Временная сложность:** `O(1)` для проверки попадания в кэш (поиск по ключу-строке).
- **Дедупликация (requestId):** Проверка `requestId` работает за `O(1)`, так как это простое сравнение целых чисел.

## 4. Принципы чистого кода

- **Принцип единственной ответственности (SRP):**
  - `searchCountries.ts`: отвечает только за HTTP-запрос и выброс ошибок (нет логики UI).
  - `mapCountryResponse.ts`: отвечает только за преобразование структур данных (нет сайд-эффектов).
  - `searchController.ts`: отвечает только за управление состоянием, дебаунс и жизненный цикл (нет работы с DOM).
  - `main.ts`: отвечает только за манипуляции с DOM (рендеринг и обработка событий).
- **Внедрение зависимостей (DI):**
  - `createSearchController` (в `searchController.ts`) принимает зависимости (`searchFn`, `onResults`, `onError`, `onLoadingChange`) в виде объекта. Это делает контроллер «чистым» и позволяет легко тестировать его без моков глобального `fetch` или DOM API.
- **DRY (Don't Repeat Yourself):**
  - Работа с DOM для рендера результатов и ошибок централизована в `renderResults` и `renderError` в `main.ts`.
- **Защитное программирование:**
  - `mapCountryResponse` изящно обрабатывает крайние случаи, когда API может вернуть строку вместо объекта (`name`), или строку вместо массива (`capital`). Также предусмотрены fallback-значения (например, `—` для отсутствующей столицы).
- **Отсутствие «магических чисел»:**
  - Значения таймингов, такие как `debounceMs` и `timeoutMs`, не захардкожены глубоко внутри контроллера. Они передаются через интерфейс `SearchControllerDeps`, что позволяет легко менять поведение снаружи.
